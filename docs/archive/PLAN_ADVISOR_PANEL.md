# 顾问面板改进计划

> 生成时间：2026-08-28  
> 状态：待评审  
> 依据：`CALCULATION_PHILOSOPHY.md`（14 条纪律 + 6 模块契约）+ 代码调查 + 运行环境调查

---

## 1. 背景与目标

### 1.1 项目概述

「创业者商业建模工作台」是面向中国小微企业主的商业财务建模系统。核心能力：用户输入项目参数 → 引擎确定性计算 → 输出收支平衡、跑道、利润等指标。系统采用「置信层+门禁+LLM 协作层」架构，引擎为唯一真相源，LLM 为只读协作者（操盘协作者角色）。

### 1.2 本次计划目标

在系统中新增**顾问面板**，将当前隐式分散在三个位置的「缺失引导」「矛盾解读」「来源叙事」收拢到一个受控出口，同时满足：

- 与引擎**共用同一动作入口**（不绕过 `apply_turn_guarded`）
- 与 14 条纪律**主动对齐**（强化 #3 #11 #12 #13，防守 #1 #6 #14，对齐 #2 #5）
- 不引入新的真相源（数字防火墙过滤 LLM 幻觉数字）

### 1.3 计划范围总述

新增顾问面板（后端 1 个 formatter + 3 个端点 + 前端 1 个面板组件 + 样式），修复前端已发现的交互 bug（重命名键漂移、分类隐藏对话），不涉及引擎核心计算逻辑修改。

## 2. 现状总结

### 2.1 代码现状

| 维度 | 现状 |
|---|---|
| 技术栈 | Python 3.12 + FastAPI + DeepSeek LLM；前端原生 JS + CSS（无框架） |
| 核心模块 | 6 模块：`field_model` / `param_guard` / `workflow_engine` / `session_state` / `param_extractor` / `formatter` |
| LLM 模块 | `llm_advisor.py`（417 行），返回 `{text, ops}` |
| 前端规模 | `app.js` 713 行，`app.css` 120 行 |
| 代码规模 | 核心模块共 5222 行 Python |
| 测试 | 260 个 Python 测试（全部通过），无前端单元测试 |
| 已知前端 bug | ① 重命名键漂移（Enter/blur 双重触发 + 失败无限重试）<br>② 改名后显示错误（restore 判断条件反了）<br>③ 点改参/决策/对比后对话消失（分类过滤隐藏消息）<br>④ 改参 vc 字段比对格式不一致（"40%" vs "40" 恒判定为已改动）<br>⑤ IME 组合输入回车误提交（拼音选词触发 finish/send） |

### 2.2 环境现状

| 维度 | 现状 |
|---|---|
| 运行时 | Python 3.12（managed）+ Node 22.22.2（managed，仅前端构建用） |
| 依赖管理 | `uv` + `pyproject.toml` + `uv.lock` |
| 外部服务 | DeepSeek LLM API（api.deepseek.com，通过 .env 配置） |
| 存储 | 默认 `MemoryStore`（进程内），可选 `PostgresStore` |
| 启动方式 | `./start.sh` 或 `python web_server.py -p 8080` |
| 可运行性 | 260 测试全部通过，本地可启动 |

### 2.3 核心结论（最突出的 3-5 个问题）

1. **LLM 输出与引擎输出空间混杂**：用户无法区分「引擎算的」和「LLM 猜的」，来源标签常被忽略
2. **缺失/矛盾/来源信息分散**：参数面板显示"—"、guard_banner 前置横幅、数值标签——用户需自己拼凑
3. **前端交互缺陷**：重命名键漂移、分类隐藏对话等 5 个已确认 bug
4. **LLM 幻觉风险**：当前 `llm_advisor` 输出中的数字无校验，若直接展示可能产生新真相源
5. **动作路径不统一**：若顾问面板新增「应用」按钮，需确保与对话区共用同一 `apply_op` 入口

## 6. 改进设计

### 6.1 架构设计

**设计内容**：新增 `advisor` 子包，作为展示层的平行模块（与 `formatter` 同级）。不改变现有 6 模块的调用关系。

**落点**：
- 新增：`src/advisor/__init__.py`、`src/advisor/advisor_formatter.py`
- 修改：`web_server.py`（新增端点）

**验收要点**：
- `advisor_formatter.py` 不 import `field_model` / `param_guard` / `workflow_engine`（不调用计算模块）
- 端点只通过 `to_llm_view(tid)` 获取只读状态

### 6.2 功能设计

**设计内容**：顾问面板输出 4 类内容——判断、风险、建议动作、依据标注。

**落点**：`advisor_formatter.py` 的 `format_advice()` 函数。

**验收要点**：
- 判断文本：LLM 输出的 `text` 字段（经数字防火墙过滤）
- 风险列表：从 `text` 中解析风险段落（正则匹配"风险"关键词）
- 建议动作：从 `ops` 中解析，每条带 `preview` 文本
- 依据标注：每条判断/风险必须关联至少一个参数字段 + 来源标签

### 6.3 数据设计

**设计内容**：顾问面板的输出 JSON 结构。

```json
{
  "judgment": "固定成本占比偏高",
  "judgment_citations": [
    {"field": "monthly_rent", "value": 15000, "source": "[用户]"}
  ],
  "risks": [
    {"text": "定价贴近变动成本", "trigger": "客单价 25 元，变动成本率 40%"}
  ],
  "actions": [
    {"op": {"field": "monthly_rent", "value": 12000}, "preview": "月固定成本→30,000"}
  ],
  "citations": [
    {"field": "monthly_rent", "value": 15000, "source": "[用户]"}
  ],
  "params_version": "a1b2c3d4"
}
```

**落点**：`advisor_formatter.py`。

**验收要点**：
- `params_version` 为参数哈希（前 8 位 md5），用于并发控制
- `citations` 中只包含来源为 `[用户]` / `[推算]` 的字段（过滤 `[候选]`）

### 6.4 接口设计

**设计内容**：3 个新端点。

| 端点 | 方法 | 输入 | 输出 | 行为 |
|------|------|------|------|------|
| `/advisor` | GET | `tid` | 顾问面板 JSON | 只读，不写状态 |
| `/advisor/preview` | GET | `tid`, `op` | `{ok, preview, reason}` | 预览动作效果 |
| `/advisor/apply` | POST | `tid`, `op` | `{ok, applied, new_params}` | 执行动作（共用入口） |

**落点**：`web_server.py`。

**验收要点**：
- `/advisor/apply` 内部调用 `validate_op(tid, op)` → `apply_op(tid, op)`，与对话区「应用 A/B」共用同一函数
- 不新增独立的动作执行路径

### 6.5 性能设计

**设计内容**：防 API 成本爆炸。

- **显式触发**：用户点击「顾问」Tab 或「顾问分析」按钮
- **自动触发**：参数哈希变化 + 5s 防抖 + 变化幅度阈值（至少 1 个关键字段变化）
- **手动刷新**：顾问面板内刷新按钮

**落点**：`app.js` 中的 `refreshAdvisor()` 函数。

**验收要点**：
- 连续改参 10 次，API 调用 ≤ 2 次（防抖后）
- 参数哈希算法只哈希 6 个关键字段

### 6.6 安全设计

**设计内容**：数字防火墙 + 来源过滤。

- **数字防火墙**：LLM 输出中任何数字必须匹配参数面板已有值，否则替换为 `[数字已过滤]`
- **来源过滤**：`citations` 中过滤掉来源为 `[候选]` 的字段（保守兜底原则）
- **动作校验**：所有动作必须经过 `validate_op` → `preview_op` → 用户确认

**落点**：`advisor_formatter.py` 的 `validate_no_computed_numbers()` 和 `_filter_citations()`。

**验收要点**：
- LLM 输出 "月固定成本大概 33,000" → "月固定成本大概 [数字已过滤]"
- 引用 `[候选]` 字段时自动过滤，或引导用户先确认

### 6.7 可维护性设计

**设计内容**：模块职责单一。

- `advisor_formatter.py`：只做格式化 + 数字防火墙 + 来源过滤，不做计算
- `app.js` 中顾问面板渲染逻辑独立函数（`renderAdvisorPanel()`）
- 样式独立 class（`.advisor-panel`、`.advisor-tag`、`.advisor-risk`、`.advisor-action`）

**落点**：新增文件 + `app.js` + `app.css`。

**验收要点**：
- `advisor_formatter.py` 的函数平均行数 ≤ 30 行
- 顾问面板渲染逻辑与对话区渲染逻辑解耦

### 6.8 可靠性设计

**设计内容**：LLM 失败降级 + 并发安全。

| 场景 | 降级行为 |
|---|---|
| API 超时（60s） | 显示「顾问暂时不可用，请稍后重试」 |
| API 返回空 | 显示「暂无建议，请先完善参数」 |
| ops 校验失败 | 显示「建议动作暂不可用，请通过对话区操作」 |
| 参数版本变化 | 丢弃旧响应，使用最新参数重新请求 |

**落点**：`app.js` 中的错误处理逻辑。

**验收要点**：
- 模拟 API 超时，顾问面板显示降级提示，不崩溃
- 快速连续改参，只响应最后一次请求

### 6.9 可测试性设计

**设计内容**：新增测试覆盖。

| 测试 | 覆盖 |
|---|---|
| `test_advisor_formatter.py` | `format_advice()` 输出结构、数字防火墙、来源过滤 |
| `test_advisor_endpoints.py` | 3 个端点的输入输出、权限校验 |
| `test_advisor_integration.py` | 顾问面板「应用」与对话区「应用 A/B」行为一致 |

**落点**：`tests/` 目录。

**验收要点**：
- 数字防火墙测试：输入含幻觉数字的 LLM 输出，验证数字被过滤
- 入口一致性测试：同一 op 通过 `/advisor/apply` 和 `/apply` 结果相同

### 6.10 兼容与部署设计

**设计内容**：向后兼容 + 缓存破坏。

- 顾问面板为新增功能，不影响现有对话区交互
- 前端资源引用加版本号（`/static/app.js?v=20260824`）
- 不修改数据库 schema（MemoryStore 无需迁移）

**落点**：`web_server.py`（版本号引用）。

**验收要点**：
- 不安装新依赖即可启动
- 旧版浏览器（无 ES6 模块支持）仍能正常使用对话区
